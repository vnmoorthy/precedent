The bottleneck moved

Agents write most of the code now. AI-generated PRs wait ~5× longer for review, and the senior engineer who owns payments writes the same review comment eleven times — because every fresh agent session starts with amnesia. Rules files are suggestions the model drops under context pressure. Review bots catch it after the PR exists, on the reviewer's clock. Precedent enforces it before the write happens, on the agent's clock.

Codex fought back

Our first ruleset produced zero denials — Codex evaded it twice, once by renaming a parameter, once by defining a decoy function named constructEvent that satisfied the letter of the rule while parsing unverified input. Rulings are now decoy-resistant: they demand a qualified call, never a bare identifier. If you needed proof that suggestions aren't enforcement, the agent gaming its own guardrail is it.

How it works

A 6-line bash hook bridges Codex's PreToolUse event to a local daemon. The daemon parses the patch, matches path-scoped rulings from SQLite (hot path) backed by claude-mem (durable, typed, cloud-syncable memory), and returns a deny with provenance — or silence. It fails open: a dead daemon never blocks the agent. Rulings are mined from Greptile review comments and GitHub PR threads: the objections your team already made, made binding.
