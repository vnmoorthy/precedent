Code-review rulings, enforced at the moment the agent writes.

01 · The problem
"For the cost of hundreds of CPU hours but only 2 or 3 minutes of their time, I'm now expected to review this." r/ExperiencedDevs · 1.9K upvotes · 438 comments
  • AI-generated PRs wait ~5× longer for first review
  • The code owner writes the same objection eleven times
  • Every fresh agent session starts from zero
02 · Why nothing holds

Suggestions are not enforcement

  • Rules files — dropped under context pressure; the model treats them as advice
  • Review bots — catch it after the PR exists, on the reviewer's clock
  • Nobody makes the team's past decisions binding at write time
03 · The system

Mine · Remember · Enforce

  • Mine recurring review objections into typed rulings — rule, path scope, origin PR, recurrence
  • Remember them in claude-mem — typed, persistent, synced across machines
  • Enforce pre-write: violating patches denied with the original PR cited, in milliseconds
  • The agent reads the denial and corrects itself

08 · Rules & sponsors

Hackathon rules

  • Codex as primary agent — wrote the engine (~1,100 lines: parser, matcher, store, daemon) across 50+ sessions; rollouts on file
  • Built during the 1–5pm window; prep limited to accounts, fixtures and keys
  • Supporting tools disclosed — Claude Code assisted on fixtures, docs and ruling curation

Sponsor stack

  • OpenAI Codex — builder and the governed agent
  • Greptile — review history is the ruling source; enabled on the repo
  • claude-mem — rulings live as typed memory (Memory Prize entry)
  • Stripe — ruling #1 encodes real webhook-signature semantics
  • DoorDash — ruling #2 encodes Drive's documented 3× redelivery
  • AWS & Modal — not used in the 4-hour build; scale path
09 · The company
